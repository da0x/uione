# @uione/react

The runtime that generated uione apps are built on: routing, live views, commands,
sign-in, and the contract a component set draws to. Apps are normally generated by
the uione compiler, `one`, rather than written by hand; this package is what the
generated code imports.

## Install

```sh
npm install @uione/react react react-dom react-router
npm install firebase   # only for @uione/react/firebase
```

React 19, React Router 7 and, when used, Firebase 12 are peer dependencies.
Node 20 or later.

## Entry points

- `@uione/react`: `App`, `screen`, the screen components (`Table`, `Form`,
  `Command`, `Live`, `Markdown`, `Pages` and the rest), `useView`, `useCommand`,
  `useAuth`, `useParam`, an in-memory data source for tests (`memorySource`), and
  the component contract's types.
- `@uione/react/plain`: `plain`, a component set that draws everything as
  unstyled, semantic HTML. Useful in tests and as a reference for writing one.
- `@uione/react/firebase`: `firebaseSource`, a data source that reads views live
  from Firestore, sends commands to the app's backend, and signs in with Google.

## Example

```tsx
import { createRoot } from "react-dom/client";
import { App, Form, Table, screen, useView } from "@uione/react";
import { firebaseSource } from "@uione/react/firebase";
import { plain } from "@uione/react/plain";

const books = screen({ title: "Books", route: "/books", nav: "Books" }, () => {
  const shelf = useView("library::shelf");
  return (
    <>
      <Table view={shelf} columns={{ title: "Title", author: "Author" }} />
      <Form command="library::book::create" fields={["title", "author"]} button />
    </>
  );
});

const data = firebaseSource({ config: { projectId: "my-project", apiKey: "..." } });

createRoot(document.getElementById("root")!).render(
  <App name="Library" screens={[books]} ui={plain} data={data} />,
);
```

## The component contract

This package decides what is on a screen and how it behaves, and a component set
(such as `plain`, or `@uione/radix`) decides only how it looks. Every prop a
component set receives is already worked out, so it never fetches, routes or runs
commands itself; the types are in `ComponentSet` and the `...Props` interfaces.

## What a component set may trust

- `PagesProps.html` is trusted: HTML made when the app was built, from the app's
  own docs, and it can be drawn as it is.
- `MarkdownProps.source` is not: it is text people wrote. A component set must
  render it without any raw HTML in it, and keep only links to safe protocols
  (https, http, mailto).

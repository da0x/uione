# 0.6.0

Released 2026-10-05. The compiler and every library move to 0.6.0 together. A
project signs people in with Google, GitHub or Microsoft, any of them, and two
words change their names, so a project for 0.5 needs `one upgrade`, which makes
both changes itself and keeps the project block lined up.

## New

- **Sign in with Google, GitHub or Microsoft, or several.** A project names each
  way people sign in on a line of its own, in the order they're offered:

  ```one
  project neotrac {
  	authentication  google
  	authentication  github
  	authentication  microsoft
  }
  ```

  With one way, Sign in goes straight to it. With more, Sign in, and a form's
  "Sign in to …", open a dialog with a button for each: Continue with Google,
  GitHub or Microsoft, each with its mark. A project that names none signs no one
  in.
- **Each way is a component of its own.** `@uione/react/firebase` has `google`,
  `github` and `microsoft`, each its own module with its Firebase provider and its
  mark, and a generated app imports only the ones its project names. Choosing
  among them is `SignIn`, a component of the component set, so radix draws it like
  the rest of the site.
- **One account, whichever way.** Someone who signs in with GitHub after signing
  in with Google, with the same email, is asked to sign in the way they did
  before, once; the second way is then added to that account, and either works
  from then on.

## Changed

- **`signin` is `authentication`.** One way to a line, and a project can have
  several. `one upgrade` renames it.
- **`signed_in` is `authenticated`.** `permission authenticated` is anyone
  signed in, any way the project offers. `one upgrade` renames it. In Go,
  `one.SignedIn` is `one.Authenticated`; the old name stays for now, marked
  deprecated.
- **The `App`'s `signin` is `authentication`, and the `Form`'s `signin` is
  `authenticated`,** as the generated code writes them.

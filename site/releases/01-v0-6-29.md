# 0.6.29

Released 2026-10-08. The compiler and every library move to 0.6.29 together. Nothing
that worked in 0.6.28 changes, so a project for it needs no edit: `one upgrade`
records the new version.

| Part | Where | Install |
|---|---|---|
| `one`, the compiler, for Linux and macOS | [GitHub releases](https://github.com/da0x/uione/releases/tag/v0.6.29) | one command, see [Install](/install) |
| `one` in a container | `ghcr.io/da0x/uione` | `docker run --rm -v "$PWD:/work" ghcr.io/da0x/uione:0.6.29 check .` |
| The builder, for deploying with nothing installed | `ghcr.io/da0x/uione-builder` | `docker pull ghcr.io/da0x/uione-builder:0.6.29` |
| `one`, the Go library backends are built on | `github.com/da0x/uione/one` | `go get github.com/da0x/uione/one@v0.6.29` |
| `infrastructure`, the Go library deploys are built on | `github.com/da0x/uione/infrastructure` | `go get github.com/da0x/uione/infrastructure@v0.6.29` |
| `@uione/react`, the app's runtime | npm | `npm install @uione/react@0.6.29` |
| `@uione/radix`, the components it draws with | npm | `npm install @uione/radix@0.6.29` |
| `@uione/compiler`, the compiler in WebAssembly | npm | `npm install @uione/compiler@0.6.29` |
## Changed

- **GitHub accounts take invitations.** Firebase doesn't vouch for a GitHub
  account's email, so signing in with GitHub now sends the access GitHub gave to the
  backend once, which asks GitHub which account it's for and which addresses it has
  verified. When it's the account they signed in with, those addresses are kept on
  their profile, in no view, and an invitation to any of them is taken. Access to
  another account adds nothing, and the access itself is kept nowhere.

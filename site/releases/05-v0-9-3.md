# 0.9.3

Released 2026-10-11. The compiler and every library move to 0.9.3 together. A
board's cards are dragged into order within their column, and a table's rows within
a tab or a page.

| Part | Where | Install |
|---|---|---|
| `one`, the compiler, for Linux and macOS | [GitHub releases](https://github.com/da0x/uione/releases/tag/v0.9.3) | one command, see [Install](/install) |
| `one` in a container | `ghcr.io/da0x/uione` | `docker run --rm -v "$PWD:/work" ghcr.io/da0x/uione:0.9.3 check .` |
| The builder, for deploying with nothing installed | `ghcr.io/da0x/uione-builder` | `docker pull ghcr.io/da0x/uione-builder:0.9.3` |

## Cards put in order on a board

```one
view board_page per board {
	issues = each issue in board {
		order by position
		number  title  stage  position
	}
}

board board_page.issues by stage over board_page.stages {
	move issue::move along board_page.steps
	reorder position
	title
}
```

- **`reorder position` in a board** puts each column's cards in order: a card is
  dragged up or down its column, with a line showing where it will land, or moved
  with Alt+↑ and Alt+↓. Dragging it to another column still moves it there.
- **A drop gives the card a position between its new neighbors',** so only it
  changes, by the entity's `update`, which may set the field. The list is ordered by
  it first, as a table's is.
- **A dropped row or card stays where it was put** while the change is on its way,
  rather than jumping back until the view catches up.

## Tables put in order within tabs and pages

- **A table with `reorder`** can now be put in order within one of its tabs, like a
  stage, or one of its pages. A row's neighbors there are still its neighbors in the
  whole list, so it goes between them. It still can't while sorted by a column or
  searched.
- **Two rows at the same place** have no number between them, so the whole list is
  numbered again in its new order, not only the rows on the screen.

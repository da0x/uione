# 0.9.8

Released 2026-10-11. The compiler and every library move to 0.9.8 together. A
workflow's stages can be written in the code, with who works each and the steps
between them, when every project works the same ones.

| Part | Where | Install |
|---|---|---|

## Stages written in the code

```one
define workflow order by stage {
	proofing  worked by proofreader
	press     worked by press_operator
	shipping  worked by shipper
	proofing -> press
	press -> shipping
	press -> proofing
	shipping -> shipped
	lease 30 minutes
}
```

- **A workflow along a field of choices** takes its stages from them. Each line
  says which roles work a stage, and each step who may take it: the roles that
  work where it starts, or those it names, as in `press -> proofing by foreman`.
- **It adds what a workflow of records does:** who holds an order and until when,
  claim, renew, release and move, and each role's queue, `order_work`. No stage or
  step is kept as a record, so a new shop starts working at once.
- **A stage nobody works is an end.** It's in no queue, and no step leaves it.
- **Mistakes are named where they're written:** a stage that isn't a choice, a
  role that isn't defined, a step out of an end, a choice nothing reaches.
- **`held([role::shipper])`** asks whether the person holds one of the roles
  named, in any command.
- **A role's name can be any word of the code's,** like `press_operator`. Before,
  a name with `_` was refused when a project was made.
- **A workflow with a mistake** is one error. Before, every role that allowed its
  commands was an error too.
- The Go library's views can keep a way for some of what they're per, with
  `When`, which each role's queue is made with.

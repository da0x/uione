# 0.9.5

Released 2026-10-11. The compiler and every library move to 0.9.5 together. Views,
entities, fields and screens each say what they mean once, a fifth front page draws
a board of work, and `one upgrade` moves a project onto all of it.

## Shorter files, said one way

`one upgrade` rewrites a project for 0.9.5 by itself. What it can't know, like a label
every screen agrees on, stays as it was and still works.

## Views take their fields bare

```one
view order_page per order {
	number  title  due  stage  stage.title  customer.name
}
```

- **In a view per something,** its fields are said bare, as a list's rows are, and
  what they point at by their own names, like `stage.title`. A screen reads
  `{order_page.stage.title}`.
- **A value named otherwise** still says what it is, like `total = count(order)`.
- `one upgrade` turns `title = order.title` into `title`.

## Who may read, said once

```one
entity shop {
	readers member
	public when visibility == visibility::public
	slug        text  required  key
	visibility  enum  public | private = visibility::private
}
```

- **Every view per a shop,** or per an order whose one field points at its shop, is
  read by the shop's members, and by anyone once the shop is public.
- **A view that says its own readers** says all of who may read it, and inherits
  nothing, so a members-only view stays members-only.
- `one upgrade` takes out a view's lines that say just what its entity does.

## Fields worked out from what they point at

```one
entity step {
	board    board    required  key
	shop     shop     = board.shop
	roles    list of role  = [role::clerk, role::printer]
}
```

- **`shop  shop  = board.shop`** is read when a step is made, in the same
  transaction, from the board it names, even a board made earlier in the same
  command. It's never given: setting it is an error.
- **A list of roles can start with roles** every shop starts with, each the one in
  the step's own shop.
- `one upgrade` drops the assignments these make unneeded.

## Labels belong to the field, and a person is one column

```one
entity order {
	number    serial  key  "#"
	packers   list of user  "Packed by"
}

table orders {
	number  title  packers  author "Opened by"
}
```

- **A field's label** is what every table, board, card, form and details call it,
  unless a screen says its own.
- **A column naming a person,** like `author` or `packers`, shows each one's name
  with their picture beside it, when the rows hold both.
- `one upgrade` joins `author.picture ""` and `author.name` into one column.

## Screens at several addresses, and headers per path

```one
header /:shop {
	component shop_header
}

screen /:shop/orders
	/:shop/orders/:status {
	layout two_columns
	table orders
}
```

- **A screen can be at several addresses,** each the same page.
- **A screen can be untitled,** and shows the site's title.
- **`under` and `layout` are lines** of the screen's own.
- **`header /:shop { ... }`** goes above every screen whose address goes on from
  that path.
- `one upgrade` moves `under` and `layout` inside, drops titles that are only the
  site's, and joins screens that say the same.

## What's new, said as a condition

- **`new when created_at > news.seen`** marks the changes a condition holds for,
  reading other views as they were when the page opened.
- **`on open dispatch reader::create`** runs once the timeline opens with something
  new in it.

## A front page called relay

`screen "Home" / landing relay` draws a front page as a board of work: the site's
sections are its cards, worked by people and by agents, and once, after the page
opens, an agent's card moves to the next stage. A timeline or a table on the screen
comes right under the board.

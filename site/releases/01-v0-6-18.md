# 0.6.18

Released 2026-10-07. The compiler and every library move to 0.6.18 together. Nothing
that worked in 0.6.17 changes, so a project for it needs no edit: `one upgrade`
records the new version.

| Part | Where | Install |
|---|---|---|
| `one`, the compiler, for Linux and macOS | [GitHub releases](https://github.com/da0x/uione/releases/tag/v0.6.18) | one command, see [Install](/install) |
| `one` in a container | `ghcr.io/da0x/uione` | `docker run --rm -v "$PWD:/work" ghcr.io/da0x/uione:0.6.18 check .` |
| The builder, for deploying with nothing installed | `ghcr.io/da0x/uione-builder` | `docker pull ghcr.io/da0x/uione-builder:0.6.18` |
| `one`, the Go library backends are built on | `github.com/da0x/uione/one` | `go get github.com/da0x/uione/one@v0.6.18` |
| `infrastructure`, the Go library deploys are built on | `github.com/da0x/uione/infrastructure` | `go get github.com/da0x/uione/infrastructure@v0.6.18` |
| `@uione/react`, the app's runtime | npm | `npm install @uione/react@0.6.18` |
| `@uione/radix`, the components it draws with | npm | `npm install @uione/radix@0.6.18` |
| `@uione/compiler`, the compiler in WebAssembly | npm | `npm install @uione/compiler@0.6.18` |
| `@uione/editor`, the editor for `.one` files | npm | `npm install @uione/editor@0.6.18` |

## New

- **Several boards to a project.** What neotrac needed for a project's product,
  marketing and executive work to each have their own board, workflow and issues:
  - `board::create { project = id  title = name }` in a command makes a board as
    `board::create` does, its body run too, like the phases of its preset.
  - In a view per issue, `each step where board == issue.board` lists the steps of
    the issue's board, and is rebuilt when they change.
  - A once may give what was made before a key existed its key.
- **Toolbars.** A command in a table's or a board's block, like `issue::create "New
  issue"`, is a button beside its search, opening its form. A board takes `search`
  too, and beside a table of the same list takes its search and toolbar. The table
  or board switch is drawn as icons, in that toolbar.
- **Tabs by a list's records.** `table project_page.issues by phase over
  project_page.phases` has a tab for each phase, in order, with its count.
- **A heading.** `heading { project::update "Edit project" }` puts buttons on the
  screen's title row, at its end.

## Fixed

- An entity named like a screen item, like a board, has its commands as buttons:
  `board::update "Edit board"` was read as the start of a board.
- A form opened from a row doesn't offer that row as a pick, and rows at the same
  position are numbered again when one is put between them.
- A search box names its fields in words: Search title, labels, phase and priority.

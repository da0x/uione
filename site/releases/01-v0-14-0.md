# 0.14.0

Released 2026-10-14. The compiler and every library move to 0.14.0 together. A list
is shown as a table, a board, a pipeline or a whiteboard, as each person picks; a
record waits on others until each has succeeded, and says so by itself; and a
stage's end is success.

## New

- **One switch for every way of showing a list.** A table, a board, a pipeline and a
  canvas of the same list, one after another, are one: Table, Board, Pipeline and
  Whiteboard, picked above them, the search box and buttons staying on that line.
  Each person's pick is kept for them; until they pick, it opens on the one whose
  `when` holds, like a board's style.
- **Dependencies, with stages kept as records too.** `define workflow issue by stage
  { depends on waits_on  done when stage.status == status::success }` keeps an issue
  from being taken or moved until everything it waits on has reached a stage whose
  status is success, saying "waiting on …". A board, a pipeline and a whiteboard show
  it waiting, a blue dot naming what, with nothing set, and it clears by itself.
- **Success, an end.** A stage's status is `success` where it was `done`; what was
  stored as done reads as success.
- **A milestone that's all done is green.** A track's record whose rows have all
  succeeded shows a green dot. `hide when empty` in a track leaves out a record none
  of the rows names.
- **A service's picture is a robot**, where a list shows people by name and picture
  and its `service` field says it's one, like an agent.
- **Inside an `each`, the command's own record is named by its entity**, like
  `link.to`.

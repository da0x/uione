# 0.8.1

Released 2026-10-10. The compiler and every library move to 0.8.1 together. `one
build` now writes an app's C++ client, so a native program, a command line tool or a
desktop app uses the app as its web pages do.

| Part | Where | Install |
|---|---|---|
| `one`, the compiler, for Linux and macOS | [GitHub releases](https://github.com/da0x/uione/releases/tag/v0.8.1) | one command, see [Install](/install) |
| `one` in a container | `ghcr.io/da0x/uione` | `docker run --rm -v "$PWD:/work" ghcr.io/da0x/uione:0.8.1 check .` |
| The builder, for deploying with nothing installed | `ghcr.io/da0x/uione-builder` | `docker pull ghcr.io/da0x/uione-builder:0.8.1` |

| `infrastructure`, the Go library deploys are built on | `github.com/da0x/uione/infrastructure` | `go get github.com/da0x/uione/infrastructure@v0.8.1` |

## A C++ client for every app

- **`cpp/<app>.hpp`.** `one build` writes one header holding a struct for every
  entity and every view, typed as the language says them, even through what a
  column points at, like `phase.title`; the ids entities are stored under, made as
  the app makes them; a function for every command; and every view, read once or
  live as it changes.
- **Built with g++ alone and a TLS library**, on
  [libember](https://github.com/da0x/libember), an independent C++ client for
  Firebase: `g++ -std=c++23 program.cpp $(pkg-config --cflags --libs botan-3)`.
- **Signing in:** with a service's key, or as a person with a refresh token or a
  GitHub or Google access token. It finds the app's Firebase settings itself, from
  the app's address.

```cpp
#include <neotrac.hpp>

neotrac::client app({.server = "https://neotrac.org"});
app.sign_in_with_key(std::getenv("NEOTRAC_KEY"));
auto listening = app.board_page("neotrac-main").listen([](const auto& page) {
	for (const auto& issue : page.issues) std::puts(issue.title.c_str());
});
```

- The site's client is kept as a reviewed target, and the checks compile every
  generated client against libember, with warnings as errors.

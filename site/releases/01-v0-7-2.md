# 0.7.2

Released 2026-10-09. The compiler and every library move to 0.7.2 together. Only
commands change what's stored now, roles and the systems that run commands are
each declared on their own, and lists say what they're in. `one upgrade` rewrites
most of what changed; roles and webhooks are moved by hand, as below.

## New

- **Only commands change records.** `dispatch board::create { ... }` runs another
  command in the same step, as the same person, its body and requires too. An
  update or a delete says which with `id = ...`, or acts on each row of an
  `each`. Deleting what's already being deleted does nothing, so two records that
  delete each other stop. `create`, `delete each`, and setting the fields of
  anything but a command's own entity are gone; `one upgrade` rewrites each.
- **Roles declared one by one.** `define role maintainer "Maintainer" in project {
  ... }` lists the commands a role allows, one a line, and the language keeps
  projects' roles as `role` and `member` records. Every command is one a role
  allows, or says who runs it: `by anyone`, `by anyone signed in` or `by owner`,
  which replace `permission`. What a deploy adds to a role reaches every project.
- **Services.** `define service github "GitHub" in project { mention::create }` is a
  system that runs commands, not a person. A webhook runs as one, `webhook github
  /hooks/github as github`, and makes things by dispatching what its service runs.
  No person may run what only services run, even by editing a project's role.
- **Lists in what they're for.** `each issue in project`, `each change in issue`,
  and `each change in issue in project`. Views say `me` for the person reading.
  `one upgrade` rewrites `of`, `where project == project.id` and `user.id`.
- **Text over lines.** Strings alone on the lines after one go on with it.
- **What's new is a view's value.** `unread = count(changes where created_at >
  seen)`, shown with `header { badge news.unread }`.

## Moving to it

`one upgrade` does most of it. By hand:

- `roles role per project from member`, and `role ... per project from member`,
  become `define role` blocks; take out the `role` and `member` entities, which the
  language declares.
- A webhook says `as` the service it runs as, declared with `define service`.

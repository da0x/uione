# 0.8.3

Released 2026-10-10. The compiler and every library move to 0.8.3 together.
Deleting a project now deletes everything it holds.

| Part | Where | Install |
|---|---|---|
| `one`, the compiler, for Linux and macOS | [GitHub releases](https://github.com/da0x/uione/releases/tag/v0.8.3) | one command, see [Install](/install) |
| `one` in a container | `ghcr.io/da0x/uione` | `docker run --rm -v "$PWD:/work" ghcr.io/da0x/uione:0.8.3 check .` |
| The builder, for deploying with nothing installed | `ghcr.io/da0x/uione-builder` | `docker pull ghcr.io/da0x/uione-builder:0.8.3` |
| `one`, the Go library backends are built on | `github.com/da0x/uione/one` | `go get github.com/da0x/uione/one@v0.8.3` |
| `infrastructure`, the Go library deploys are built on | `github.com/da0x/uione/infrastructure` | `go get github.com/da0x/uione/infrastructure@v0.8.3` |
| `@uione/react`, the app's runtime | npm | `npm install @uione/react@0.8.3` |

| `@uione/compiler`, the compiler in WebAssembly | npm | `npm install @uione/compiler@0.8.3` |



## Deleting a project, and all it holds

- **A project's own records go with it.** Deleting the entity a `define role` is
  `in`, like a project, deletes its roles, the members that give its people their
  roles, and its services with their keys, which stop working at once. A
  service's profile stays, so what it did is still named. The rules that keep a
  project from losing its last maintainer, or a role its people hold, don't stand
  in the way of the whole project going.
- **History goes with what it's about.** A deleted entity's own history is deleted
  with it, and so are the numbers counted for it, like a project's issue numbers.
  A project made again under the same name starts from issue 1, and never shows
  the old one's history, even to someone else who takes the name.
- **A dispatched delete does what its command does.** Deleting a service through
  `dispatch` takes its key, as deleting it directly does.
- **Confirming by typing.** A form may ask only for what its command is sent
  besides its fields, like `input address text`, with no view behind it. It acts on
  what its page's address names, and a form that deletes that goes, once done, to
  the address above it.

```one
command project::delete {
	input address text
	require address == slug  "type the project's address to delete it"
	each issue where project == id {
		dispatch issue::delete
	}
}

screen "Settings" /:project/settings {
	section "Delete this project" color red {
		project::delete "Delete project" form "Delete it for good" {
			address "Type its address to confirm"
		}
	}
}
```

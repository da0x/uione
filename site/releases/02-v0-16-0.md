# 0.16.0

## 0.16.1

Released 2026-10-17. The compiler and every library move to 0.16.1 together.

- **A workflow's steps work again in an app with organizations.** Once an app had
  roles in two places, like an organization's and a project's, checking a step or a
  claim stopped at the first set and refused everyone. Each set that doesn't reach
  the record is now passed over.
- **A change rebuilds only the views that show what changed.** An agent's progress
  no longer rebuilds a project's page and every list of its issues, only the pages
  that show progress, which cuts the database reads an agent costs.
- **A board's New issue button in the desktop and terminal apps.** A board shown as
  a board had no buttons there; it now has them above it, as on the web.
- **A comment is one box on the web**, not its text in a second frame inside it.
- **A document page on the web is set like the desktop's**: its title and words in
  the document's column, smaller than the document, and the document's text at 14px.
- **uione.io lists one release per 0.x line**, and links to uione's Open Collective.

## 0.16.0

Released 2026-10-16. The compiler and every library move to 0.16.0 together.
Charts and monitors, in every app: a record's numbers drawn over time as btop draws
them, and records whose status changes listed as btop lists processes. A card shows
how far it is in its stage, a tally's bar shows how far along it is, and the desktop
draws the web's icons.

### New

- **Charts.** `chart agent_page.stats.cpu "CPU" percent` draws a run of numbers over
  time, newest at the right: a line over a soft fill, its title, its latest value
  and the top of its scale, and the value under the pointer on the web. `charts
  agent_page { ... }` draws several side by side. Values read as they are, or as
  `percent`, `bytes`, or `rate`, bytes a second. In the terminal they're braille
  dots, filled below the line, as btop draws its graphs. `data` holds lists of
  numbers for them, up to 600 a name.
- **Monitors.** `monitor agents.agents { status status ... }` lists records whose
  status changes from one thing to another, like agents or machines, as a process
  list: a row each under a heading, its dot and state and for how long, what it's
  doing, how far, and a small line of each thing it reports. One not heard from for
  `seen`'s seconds is shown offline.
- **Progress on cards.** A card whose holder says `step` and `steps` in its data
  shows how far it is in its stage: a thin bar on a board, a whiteboard and a
  pipeline, btop's squares in the terminal.
- **The desktop draws the web's icons.** A button or link naming one is just the
  icon, its name shown when pointed at, and the view switch is icons too. A new
  icon, `robot`, is for what programs do, like a project's agents.
- **Views remembered between runs.** The desktop and terminal apps open each page's
  list the way it was last shown, as the web does.
- **Filters read through what rows point at**, and can keep what isn't so, like
  `only person.service != true`.

### Fixes

- **A tally's bar shows how far along it is**: what's done solid from the left,
  what's under way in a tint, what failed in red, and what hasn't started left as
  the empty track. A milestone with nothing started no longer looks complete.
- **A count through two fields that point elsewhere keeps to both**, like a
  milestone's issues done at a successful stage on a public board, rather than
  every issue on a public board. Stored views are rebuilt once, so what they hold is
  right too.
- **The desktop pipeline is dense**, a card a line, as on the web. A card's details
  wrap rather than run out of it, and a milestone is picked by a click anywhere on it.
